# prompt-log

프로젝트 **의사결정·주제 저널**. 대화 전문 아카이브가 아니다.

| 구분 | 역할 |
|------|------|
| **PLAN.md / AGENTS.md** | 구현·행동의 SSOT (최종 권위) |
| **prompt-log/** | 왜 그렇게 했는지, 어떤 대안을 버렸는지 (근거·히스토리) |

최종 결정이 구현 범위에 영향을 주면 **반드시 PLAN/AGENTS에도 반영**한다. 로그만 갱신하고 SSOT를 비워 두지 않는다.

## 언제 쓰는가

**`/log`를 사용자가 요청하거나, 사용자가 로그 기록을 명시할 때만** 갱신한다.  
매 턴·매 커밋·자동 append 금지.

남기기 좋은 것:

- 설계·아키텍처 선택 (예: JWT vs 세션)
- API/스키마/데이터 모델 결정
- 시도했다가 버린 접근과 이유
- 사용자가 명시한 제품·범위 결정
- UC 구현 중 막힌 지점과 해법 요약

남기지 않는 것:

- 단순 오타·포맷·린트 수정
- “파일 읽어줘” 수준의 대화
- 시크릿, API 키, 토큰, 개인정보
- PLAN에 이미 그대로 있는 수용 기준 복붙

## 구조

```
prompt-log/
├── README.md          # 이 파일 (운영 규칙)
├── INDEX.md           # 주제 목록 (항상 최신 유지)
└── <topic-slug>.md    # 주제/결정 단위 파일 (/log 로 생성·갱신)
```

- **주제/결정 단위 파일** — 날짜 롤링 파일이 아니라 주제 슬러그 파일
- **Git 추적** — 팀과 공유. `.gitignore`에 넣지 않음
- **갱신 트리거** — `/log` (또는 동등한 명시 요청) 만

## `/log` 사용

```text
/log
/log auth-jwt-vs-session
/log "Repository를 Protocol로 둔 이유" decided
```

에이전트는 `.grok/skills/log/SKILL.md` 절차를 따른다.

1. 주제 슬러그 확정 (없으면 대화에서 추론 후 확인)
2. `prompt-log/<slug>.md` 생성 또는 기존 파일 섹션 갱신
3. `INDEX.md` 행 추가/수정
4. 범위에 영향 있으면 PLAN/AGENTS 반영 여부 안내

## 읽기

에이전트는 **매 턴 전체를 읽지 않는다.**  
새 세션 시작·관련 UC 작업·설계 재검토·사용자가 지정했을 때만 `INDEX.md` → 관련 주제 파일 순으로 참조한다.
