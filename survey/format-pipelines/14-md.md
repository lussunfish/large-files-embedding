# .md 권장 파이프라인

- 배경: 시장품질 팀 위키, 8D 초안, 회의록 마크다운을 RAG/MCP에 넣을 때 헤더를 섹션 경계로 쓴다.
- 관련 문서: `../market-quality-rag-improvement.md`, `README.md`

## 결론

`.md`는 가족 E다. **기본은 Docling 없이 헤딩 분할이다.** ATX(`#`)·Setext(`---` / `===`) 헤더가 곧 목차다. 헤딩에서 자르고, 펜스 표는 table 청크로 둔다. YAML 프론트매터는 본문이 아니라 메타데이터다. 통합 `DoclingDocument` JSON이 필요할 때만 Docling Markdown 백엔드(marko)를 선택으로 켠다. 긴 파일을 통째로 임베딩하지 않는다.

권장 한 줄:

```
.md → 인코딩(UTF-8) + 프론트매터 분리
    → ATX/Setext 헤더 트리
    → 섹션 청크 + fenced table 청크
    → Milvus (heading_path 필터)
    → MCP: get_outline / get_section
```

| 선택 | 판단 |
|---|---|
| Docling PDF/Word 파이프라인 | 하지 말 것. 과하다 |
| 헤더 기준 섹션 분할 | **기본 경로** |
| Docling Markdown 백엔드 (통합 JSON) | 선택. 기본은 아님 |
| 파일 전체를 하나의 벡터 | 짧은 메모만. 긴 문서는 금지 |
| 고정 토큰 윈도우만 사용 | 헤더가 있을 때는 하지 말 것 |
| 프론트매터를 본문에 임베딩 | 하지 말 것. 메타로 승격 |
| 펜스 표를 문장으로 평탄화 | 하지 말 것 |

## 권장 파이프라인

```
업로드 .md
  1. 시그니처
       텍스트 + 마크다운 문법. 바이너리면 재분류
  2. 프론트매터
       --- yaml ---  → 제품, 차종, 기간, 문서유형
  3. 블록 파싱
       ATX / Setext 헤더
       문단, 리스트, 코드펜스
       파이프/펜스 표
  4. 청크
       헤딩 경로 breadcrumb + 섹션 본문
       표는 type=table, 헤더 행 유지
       긴 섹션만 토큰 상한으로 분할 (같은 heading_path)
       (선택) Docling Markdown 백엔드 → 통합 JSON 후 HybridChunker
  5. 인덱싱
       본문·표 → Milvus 하이브리드
  6. MCP
       get_outline, get_section, get_table, search_passages
  원본 .md 보관
```

## 단계별 권장

### 1. 헤더가 청크 경계다

```markdown
# 2024 OO 차종 8D
## 1. 현상
## 2. 원인
### 2.1 공정 조건
## 3. 대책
```

이 트리가 `get_outline` / `get_section("3. 대책")`이다. `#`를 지우고 문장만 이어 붙이면 Word에서 Heading을 버리는 것과 같다.

- ATX (`#` … `######`)를 우선한다.
- Setext는 `제목` 다음 `===` / `---` 이다. 수평선 `---` 과 혼동하지 않는다.
- 헤더가 거의 없으면 문단(빈 줄) 단위다. 그다음에 토큰 상한을 쓴다.

breadcrumb를 청크 앞에 붙인다.

```text
[문서] 2024 OO 차종 8D
[섹션] 2. 원인 > 2.1 공정 조건
[본문] ...
```

### 2. 표와 코드펜스

- GFM 파이프 표는 table 객체다. 본문 검색과 분리한다.
- 표가 길면 헤더를 각 조각에 반복한다.
- 코드펜스(로그, 측정값 dump)는 코드 청크다. 서술과 섞지 않는다.
- HTML 혼재 표(`<table>`)는 [13-html.md](13-html.md) 규칙을 따른다.

엑셀 원장을 마크다운 표로 붙여 넣은 파일은 행이 많으면 가족 C를 검토한다. 서술 8D 안의 작은 집계면 여기 둔다.

### 3. 프론트매터 → 메타

```yaml
---
product: OO
carline: AB-12
doc_type: 8D
period: 2024-09
---
```

이 필드는 Milvus 필터다. 본문 임베딩에 `product: OO` 줄을 넣지 않는다. 프론트매터가 없으면 첫 헤더·파일명에서 뽑는다.

인코딩은 UTF-8이 기본이다. UTF-8 BOM은 첫 헤더 파싱을 깨뜨릴 수 있어 제거한다.

### 4. 긴 파일

위키 dump·연간 품질 노트는 수천 줄이다. 파일 단위 임베딩은 하지 않는다.

- 검색은 섹션 청크
- 답변은 부모 섹션 (`get_section`)
- Codex 컨텍스트에 파일 전체를 넣지 않는다

MCP는 `search` 하나가 아니다. 헤더 트리를 주고 해당 장만 읽게 한다.

Docling Markdown 백엔드(marko)는 공식 입력이다. 다른 포맷과 같은 `DoclingDocument` JSON이 필요할 때만 선택으로 켠다. PDF/Word 파이프라인에 MD를 태우지 않는다. 레이아웃 모델 비용만 늘고, 헤더 정보가 왕복에서 손실될 수 있다. 기본 입고는 헤딩 분할이다.

## 흔한 실패

- 파일 전체를 한 벡터에 넣어 현상과 대책이 같은 점수가 된다.
- `#`를 일반 텍스트로 남겨 청크가 통짜가 된다.
- 프론트매터 YAML이 모든 검색 top-k를 차지한다.
- 펜스 표의 구분 행(`|---|`)이 본문으로 임베딩된다.
- Setext `---`를 수평선으로 읽어 제목이 사라진다.

## 하지 말 것

- Docling PDF/Word 파이프라인에 MD를 태우기
- 짧은 위키까지 Docling을 기본 파서로 강제하기
- 긴 `.md`를 통째로 임베딩하거나 MCP 응답으로 dump
- 마크다운을 PDF로 인쇄해 가족 B로 보내기
- 표를 한 줄 문자열로 평탄화
- 원본을 지우고 청크만 남기기
